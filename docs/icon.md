# 应用图标

极简结构：**薄荷底板 + 一块深色斜块 + 纯白 `>_`**。三个元素，无渐变、无阴影、无描边。

## 为什么是这个结构

此前试过灯塔剪影、毛线编织的 N、白底绳环，都栽在同一件事上——细节太密。
缩到 32px 时，渐变、纹理、细笔画会被缩放算法平均掉，最后只剩一团颜色。

PowerShell 的图标能活下来靠的是**大面积实心块 + 一根粗笔画**，任何尺寸都有足够的像素预算。
本图标沿用这个结构，只把配色换成品牌薄荷 `#5DCAA5`。

## 几何（1024 画布）

| 项 | 值 |
|---|---|
| 底板 | 满幅，圆角 `rx=232`（22.5%，接近 Win11 观感） |
| 斜块 | `576×502`，上下边错位 `112`（斜边倾角 ≈12.6°，与 PowerShell 同向） |
| 符号笔画 | 宽 `68`，圆头 |
| `>` | 跨度 `166×230` |
| `_` | 长 `92`（约为 `>` 宽度的 55%） |
| `>` 与 `_` | 底边齐平，间隔 `16` |
| 符号组偏移 | 右 `26`、下 `8` |

两个容易被忽略的点：

1. **符号包围盒必须把圆头算进去**（round cap 各外扩 `sw/2`）。斜块重心偏右上，
   纯几何居中会被读成「偏左上」，所以要整体右下微移。
2. **底板不能用近白**。实测近白底（PowerShell 那种）在浅色任务栏上会整块融进背景，
   视觉上只剩里面那块深色，等于图标凭空小一圈。

## 三段对比度

| 关系 | 对比度 |
|---|---|
| 白色符号 / 深色块 | 15.26:1 |
| 深色块 / 薄荷底 | 7.60:1 |
| 薄荷底 / 深色任务栏 `#1F1F1F` | 8.21:1 |
| 薄荷底 / 浅色任务栏 `#F0F4F8` | 1.82:1 |

前两条撑起小尺寸的可读性。最后一条偏低，是纯白背景（如资源管理器缩略图）
在 16–24px 时外缘会发虚的原因；如果确有必要，把底板压深到 `#3FB98E` 可提到约 2.6:1。

## 各尺寸实测

| 尺寸 | 表现 |
|---|---|
| 256 / 128 / 64 / 48 | `>_` 清晰 |
| 32 | 仍可辨认 `>_` |
| 24 | 开始糊，靠薄荷块暗示含义 |
| 16 | 只能认出「薄荷圆角方块里有块深色内容」 |

## 重新生成

```bash
cd icon-design
python gen.py       # 产出 icon.svg
node render.mjs     # 光栅化 icon-1024.png（用宿主 playwright-core 驱动本机 Chrome）
npx tauri icon icon-1024.png -o icons
```

然后替换：

- `src-tauri/icons/`：`32x32.png` `64x64.png` `128x128.png` `128x128@2x.png`
  （同图另存为 `256x256.png` 与 `512x512.png` / `icon.png`）、`icon.ico`、`icon.icns`
- `src/assets/app-icon.png`：顶部栏图标，64×64
  （会被 vite 内联成 base64 打进 `App-*.js`，所以没有独立资源文件）

## 换图标后必须重新构建

`src-tauri/build.rs` 里有 `println!("cargo:rerun-if-changed=icons");`。
**没有这一行时，只替换 `icons/` 再构建，exe 内嵌的仍是旧图标**——因为
`tauri_build::build()` 不会为 `icons/` 发 `rerun-if-changed`，build script 不重跑，
`target/release/build/nexus-term-*/out/resource.lib` 保持旧字节。

校验方法（不需要 pefile）：解析 `icon.ico` 的目录表取出每档原始字节，
到 `nexus-term.exe` 里 `bytes.find()`，命中即内嵌。
注意 NSIS 安装包里的图标被 LZMA 重编码，按字节比对必然查不到，不能作为失败依据。
